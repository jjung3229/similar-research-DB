# VoiceBridge — 회의 녹음 → 녹취록 → 회의록 (로컬 전용)

> **상태: 기획 확정 전 중단된 프로토타입입니다.**
> 구조를 눈으로 확인하려고 먼저 짜본 골격이며, 기획이 확정되면 그에 맞춰
> 다시 정리합니다. 지금 상태로 설치·실행하지 마세요. 미완성 부분이 있습니다.

## 왜 이 구조인가

네이버 클로바(노트/보이스)를 쓸 수 없는 두 가지 이유 — 월 구독료와 사내 보안 —
중 보안 쪽이 설계를 지배합니다. 그래서 **음성 데이터가 사내망 밖으로 나가지 않는 것**을
1원칙으로 잡았습니다. 전 과정이 로컬에서 돌고, 외부 API 호출이 코드에 없습니다.

```
[입력 어댑터]  →  [전사 엔진]  →  [회의록 엔진]  →  [출력]
 파일 업로드       faster-whisper   LLM / 규칙기반    MD · TXT · JSON
 (실시간 마이크)   + 화자분리                         (+ 선택적 TTS)
```

세 단계를 한 앱 안에 두되 모듈로 끊어, 회의록 엔진만 나중에 교체할 수 있게 했습니다.
실시간 녹취는 "또 하나의 입력 어댑터"일 뿐이라 뒷단을 그대로 재사용합니다.

## 미정 상태로 남은 결정들

1. 회의록 생성용 LLM을 어디서 돌릴 것인가 (사내 GPU / 개인 PC / 승인된 사내 게이트웨이)
2. 실시간 녹취를 1단계 범위에 넣을 것인가
3. 배포 형태 — 개인 PC 설치형인가, 사내 서버 공용인가
4. 사내 표준 회의록 양식 반영 여부

## 디렉터리

| 경로 | 역할 |
|---|---|
| `app/config.py` | 설정. 오프라인 모드에서 원격 호출 차단 |
| `app/audio.py` | ffmpeg 변환·wav 병합 |
| `app/stt/` | 전사 엔진 (faster-whisper) |
| `app/diarize/` | 화자 분리 (pyannote, 선택) |
| `app/text/` | 녹취 텍스트 정리 — 간투어 제거, 반복 환각 접기, 청킹 |
| `app/minutes/` | 회의록 생성 — LLM 백엔드 / 규칙 기반 폴백 |
| `app/tts/` | 음성 합성 (piper · melo · OS 내장) |
| `app/live.py` | 실시간 마이크 입력 어댑터 |
| `app/pipeline.py` | 전체 흐름 조립 |
| `app/jobs.py` · `app/server.py` | 로컬 웹 UI용 작업 큐와 API |
